# Codyssey 1-1 미션 코치 (`codyssey-mission`)

평가 항목 1~5를 모두 충족하면서, **작성자 스스로 원리를 이해해 남에게 설명할 수 있는 수준**으로 공부하고 `README.md`와 `docs/` 상세 문서를 완성하는 5단계 절차다.

## 문서 역할 분리

모든 내용을 `README.md` 한 파일에 몰아넣지 않고, 역할에 따라 나눈다. 모든 링크는 저장소 내부 상대 경로만 쓴다([docs-editing.md](../../rules/docs-editing.md)).

| 파일 | 역할 | 대응하는 평가 항목 |
|---|---|---|
| `README.md` | **대문·체크리스트 라우터·재현 요약** — 디렉토리 구조 기준, 포트/볼륨 재현 방법, 항목 1~5 체크박스 요약 및 상세 문서 링크 | 전체 요약 + **항목 2** |
| `docs/01-verification-log.md` | **기능 동작 검증 흔적** — 9개 체크박스별 실제 실행 명령어, 터미널 출력 로그, 검증 포인트 | **항목 1 (9개)** + **항목 5 (보너스)** |
| `docs/02-core-principles.md` | **핵심 기술 원리 노트** — `[한 줄 결론] → [도식/비교표] → [내 설명·실습 근거]` 3단 구조 | **항목 3 (4개)** |
| `docs/03-deep-interview-qa.md` | **심층 인터뷰 & 트러블슈팅** — 일부러 실패해 본 실험(`가설 → 확인 → 조치`)과 `qa-prep` PREP 구술 카드 | **항목 4 (3개)** |

## 5단계 진행 순서

단계마다 사용자가 먼저 이해·작성하거나 직접 실행해 보고, Claude는 질문·힌트·리뷰로 돕는다([review-mode.md](../../rules/review-mode.md)). 한 번에 최대 2개까지만 묻는다.

```mermaid
flowchart LR
    S1["1단계: 핵심 원리 공부<br/>(항목 3 → 02-core-principles)"] --> S2["2단계: 구조·재현 설계<br/>(항목 2 → README 설계 절)"]
    S2 --> S3["3단계: 실습 & 실패 실험<br/>(항목 1·5 → 01-verification-log)"]
    S3 --> S4["4단계: 심층 인터뷰 카드<br/>(항목 4 → 03-deep-interview-qa)"]
    S4 --> S5["5단계: 최종 README 조립<br/>(체크박스 완료·링크 검증)"]
```

### 1단계. 핵심 기술 원리 4가지 먼저 잡기 (항목 3 → `docs/02-core-principles.md`)

실습 명령어를 치기 전에 아래 4가지 원리를 먼저 공부하고 내 말로 설명할 수 있는지 점검한다.

1. **이미지 vs 컨테이너**: `빌드(Build) / 실행(Run) / 변경(Mutate)` 3가지 관점에서 차이를 구분해 설명할 수 있는가?
2. **컨테이너 내부 포트와 포트 매핑(`-p`)**: 왜 컨테이너 내부 포트로 호스트에서 직접 접속할 수 없고 포트 매핑이 필요한가?
3. **절대 경로 vs 상대 경로**: 각각 어떤 상황(스크립트 고정 위치 vs 프로젝트 폴더 이동/협업)에서 선택하는가?
4. **파일 권한 숫자 표기(`755`, `644`)**: `r(4)·w(2)·x(1)` 합산 규칙과 소유자/그룹/기타 3자리 결정 규칙, 디렉토리에 `x` 권한이 필요한 이유를 설명할 수 있는가?

### 2단계. 동작 구조 설계 (항목 2 → `README.md` 설계 절)

1. **디렉토리 구조 기준**: 왜 `app/`, `Dockerfile`, `docs/` 등으로 나눴는지 역할과 변경 빈도 기준으로 적는다.
2. **포트/볼륨 재현성**: 다른 사람이 저장소를 클론했을 때 어떤 명령어·설정 파일(`Dockerfile`, `docker-compose.yml` 등)로 똑같은 포트와 볼륨 상태를 재현할 수 있는지 정리한다.

### 3단계. 기능 동작 검증 9개 실습 & 일부러 실패해 보기 (항목 1·4·5 → `docs/01-verification-log.md`)

아래 9개 항목을 직접 실행하고 명령어와 결과를 기록한다.

- [ ] 1-1. 터미널 기본 명령어로 폴더/파일 생성·이동·삭제 흔적 (`mkdir`, `touch`, `mv`, `cp`, `rm`)
- [ ] 1-2. 파일 권한 변경 결과 확인 (`chmod 755`, `chmod 644`, `ls -la`)
- [ ] 1-3. `docker --version` 출력 및 Docker 데몬 동작 상태 확인 (`docker info`)
- [ ] 1-4. `docker run hello-world` 정상 실행
- [ ] 1-5. 이미지/컨테이너 목록 확인 및 정리 흔적 (`docker ps -a`, `docker images`, `docker rm`, `docker rmi`)
- [ ] 1-6. `Dockerfile`로 이미지 빌드 (`docker build -t ...`)
- [ ] 1-7. 매핑된 포트로 접속 확인 (`docker run -d -p ...`, `curl -i`)
- [ ] 1-8. Docker 볼륨 데이터가 컨테이너 삭제 후에도 유지되는지 확인 (`docker rm -f` 후 같은 볼륨 재마운트)
- [ ] 1-9. Git 설정 및 GitHub 연동 확인 (`git config --list`, `git remote -v`, `git status`)

> **필수 실험 (항목 4 인터뷰 근거 확보):**
> 1. **포트 충돌 실험**: 이미 컨테이너가 떠 있는 호스트 포트로 컨테이너를 하나 더 띄워 에러(`port is already allocated` / `address already in use`)를 발생시키고, `lsof -i :<포트>`와 `docker ps`로 원인을 찾는 과정을 기록한다.
> 2. **데이터 유실 비교 실험**: 볼륨 없이 컨테이너 내부에 파일을 쓰고 삭제했을 때(유실)와, 볼륨(`-v`)을 연결하고 삭제 후 재실행했을 때(유지)를 비교 기록한다.

### 4단계. 심층 인터뷰 3문항 구술 훈련 (항목 4 → `docs/03-deep-interview-qa.md`)

[`qa-prep`](../qa-prep/SKILL.md) 스킬의 PREP(결론 → 이유 → 사례/근거 → 결론) 구조를 사용해 3가지 질문에 대한 답변 카드를 완성한다.

1. "호스트 포트가 이미 사용 중"이라 포트 매핑이 실패한다면, 어떤 순서로 원인을 진단할지 설명할 수 있는가?
2. 컨테이너 삭제 후 데이터가 사라진 경험이 있다면, 이를 방지하기 위한 대안을 설명할 수 있는가?
3. 이 미션에서 가장 어려웠던 지점과 해결 과정(`가설 → 확인 → 조치`)을 근거와 함께 설명할 수 있는가?

### 5단계. 최종 `README.md` 조립 및 무결성 검사

1. `docs/01~03.md`가 모두 채워지면 `README.md`의 체크박스를 `[x]`로 갱신하고 각 항목 옆에 한 줄 근거와 상세 문서 링크를 연결한다.
2. 커밋 전 검증을 실행한다:
   - 링크 검사: `bash .claude/hooks/check-links.sh`
   - 비밀값·개인 경로 검사: `bash .claude/hooks/check-secrets.sh --staged`
